# 모바일 앱 구현 규칙

이 파일은 `apps/mobile/`에 적용한다. 공통 규칙은 저장소 루트의 `AGENTS.md`를 따른다.

- React Native와 Expo Router를 사용한다. `app/`에는 화면과 이동 경로를 두고, 화면에서 커지는 기능 코드는 `src/features/<기능>/`으로 분리한다.
- 여러 화면에서 같은 역할로 쓰는 버튼, 입력창, 카드 등의 UI는 공통 컴포넌트로 만들고 동일한 컴포넌트를 재사용한다. 한 화면에서만 쓰는 요소는 해당 기능 안에 둔다.
- TypeScript의 `strict` 설정을 유지한다. API 요청·응답 타입을 명시하고 `any`로 오류를 숨기지 않는다.
- 서버 요청과 오류 처리는 공통 API 모듈에 모은다. 화면에서 API 주소와 요청 형식을 반복해서 작성하지 않는다.
- 서버 데이터를 보여주는 화면에는 로딩, 빈 목록, 오류 상태와 다시 시도할 방법을 제공한다. 긴 음식점 목록은 `FlatList`를 사용한다.
- 남위례·가락동은 위치 권한 없이 직접 선택할 수 있게 한다. 현재 위치 기능을 사용자가 선택할 때만 필요한 위치 권한을 요청한다.
- 버튼과 입력 요소에 읽을 수 있는 이름, 충분한 터치 영역, 누른 뒤의 피드백을 제공한다. 화면은 안전 영역과 글자 크기 변경을 고려한다.
- `EXPO_PUBLIC_` 환경 변수에는 공개 가능한 설정만 둔다. 비밀키나 서버 전용 토큰을 앱 코드에 넣지 않는다.
